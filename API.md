# Shared numerical package contract

`vectie/moonnum` version 0.1.0 is a local, unpublished independent module. Its root package preserves the complete former `learning_numeric` public API: `Tape`, `Value`, `Rng`, `MLP`, `Adam`, `Normalization`, `finite` and `fit_normalization`. Parameters retain the original flattened row-major `[output,input]` weights followed by each layer's biases. All existing training and checkpoint arrays remain `Double`.

`vectie/moonnum/geometry` owns `Vec3`, `Basis3`, `Transform3` and their constructors/methods copied verbatim from MoonMoon's `src/moonphys/vector.mbt` and `transform.mbt`.

Additional packages are `vectie/moonnum/tensor` (explicit F32/F64 strided tensors), `vectie/moonnum/linalg` (pivoted solve and rank-revealing QR least squares), and `vectie/moonnum/blas` (optional native dynamically loaded CBLAS, explicit portable fallback). All packages pass `moon check --target all`; generated `pkg.generated.mbti` files document exact checked signatures.

Root additions are `Tape::linear(parameters,inputs,outputs,offset?=0)`, `Tape::node_count()` and the optional `Adam::step(...,gradient_trace?=(raw,applied,norm)=>...)` callback. Existing call sites need no changes. `linear` accepts the original flattened weight/bias layout, creates one output node per neuron plus a single layer reverse kernel, and differentiates both inputs and parameters. It snapshots the bound Value arrays so caller array replacement cannot change the graph. `MLP::forward` uses this kernel. `MLP::predict` now evaluates directly without allocating a Tape. Hidden SiLU and left-to-right row sums retain the old forward arithmetic; no BLAS is silently selected for an existing model. Reverse accumulation order across shared branches can differ at floating-point roundoff level.

`Adam::step` passes copies of the actual raw gradient and actual norm-then-value-clipped gradient to `gradient_trace` before moments, step count or weights change. Mutating these callback arrays cannot change the optimizer update. This is an observation hook, not a replacement numerical path.

The optimizer rejects negative or exhausted Int32 step counters before tracing or changing state. QR rejects nonfinite column norms and reflection intermediates, including overflow from finite inputs; it does not silently reinterpret overflow as rank deficiency.

Adam checkpoints retain the existing Int32 counter layout. `step` rejects restored/decoded negative or exhausted (`2147483647`) counters before invoking the trace or mutating state; the last valid increment is from `2147483646` to `2147483647`. QR checks every candidate column norm and reflection result for nonfinite values, raising `LinearAlgebraError::Invalid` on representational overflow rather than silently converting an overflowing finite-input matrix to a rank-zero result.

`linalg.least_squares(a,b,rcond?=1e-12)` accepts row arrays `a[m,n]` and `b[m,nrhs]`, returns `LeastSquares {solution[n,nrhs],rank,residual_sum_squares[nrhs],condition_estimate,pivots[n]}` and raises `LinearAlgebraError` for invalid/nonfinite inputs. Column-pivoted Householder QR computes a rank-revealing basic solution without normal equations. Rank deficiency is explicit; free pivoted coordinates are zero, so this is not a minimum-norm pseudoinverse. `condition_estimate` is the initial largest column norm divided by the smallest accepted R diagonal, a diagnostic rather than a certified matrix condition number. `solve(a,b,tolerance?=1e-12)` uses scaled partial-pivot LU on square matrices, multiple RHS and copied inputs, raising on a small relative pivot.

Tensor constructors copy input data. `shape()`, `strides()` and `to_array()` return copies. `view(shape)` requires contiguous order and equal element count; `reshape(shape)` materializes noncontiguous layouts; no inferred `-1` dimensions are accepted. `transpose`, `permute`, `slice(axis,start,length,step?=1)` and `broadcast_to` share storage. Slice uses an explicit length and supports negative starts/steps. Mutating zero-stride broadcasts intentionally changes the shared scalar; callers needing independence use `clone()`. Empty sums are zero and empty means are IEEE NaN. Binary arithmetic requires equal dtypes and follows trailing-axis broadcasting. `sum/mean(axis?,keepdim?=false)` and vector/matrix/batch `matmul` are implemented. This is a focused numeric API, not NumPy compatibility.

F32 uses actual Float storage. Primitive binary outputs round to Float; ordered sums and portable matmul round each product and accumulation in Float32. Generic `map` callbacks and transcendental helpers evaluate their inner expression in Double and then round the result, so compound callback expressions and libm results do not promise bitwise equivalence to Float32-only kernels. Existing root training APIs stay Float64.

`blas.Backend::portable()` is deterministic portable row-major accumulation and never searches the host. `Backend::load(path)` dynamically opens exactly the supplied library name/path and requires both LP64 `cblas_dgemm` and `cblas_sgemm`; failure raises `BlasError::Unavailable` instead of silently falling back. ILP64 providers with the same symbol names must not be passed: the caller is responsible for selecting the declared LP64 ABI. Handles are GC-managed and close the dynamic library. Native `gemm/gemm_f32` copy inputs to call-local contiguous arrays. `Tensor::matmul(other,backend?=...)` explicitly packs strided batches and selects this backend; omitted backend uses portable Tensor kernels. Provider threading, fused arithmetic and summation order are not controlled and can change rounding. Non-native dynamic loading fails explicitly while portable GEMM remains available. POSIX C syntax was checked locally; platform loading and linking were not exercised. On Linux systems predating merged libdl, the consumer may need `-ldl` in its native linker flags. Windows loader code is supplied but was not cross-compiled or executed here.

The geometry extraction preserves all original public names/methods, and additionally makes the previously package-private `normalized_axis` public because other extracted physics files use it. Its zero-axis fallback remains the original positive Z axis.

Only type checks, interface generation, formatting and C syntax checks are authorized in this task. Tests and differential fixtures are supplied as source and remain unexecuted.
